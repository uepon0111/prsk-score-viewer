# prsk-score-viewer v2 — 描画エンジン刷新版

GitHub Pages で運用中のプロセカ譜面ビューア（単一 `index.html` アプリ）に対し、要望 A〜E の改善を行った版です。
曲一覧・キャッシュ管理・静的 SVG 譜面表示など対象外の機能は元のまま温存し、再生まわり（`buildPlay` / `playerMain` / `openPlayer` / 再生設定）を置換・拡張しています。

## 配置方法（GitHub Pages）

このフォルダの中身をそのままリポジトリに置いてください（`index.html` と `assets/` の相対関係を維持）。

```
index.html
assets/
  notes_01.png / notes_02.png        ノーツスキン（アトラス画像）
  notes_01.atlas.json / notes_02.atlas.json  切り取り座標表
  effect.png / effect.atlas.json     エフェクトアトラス（8×8 グリッド定義）
  stage.png (2048×1176) / stage_lane.png (1920×1080) / bg_overlay.png
  long_band_01.png / long_band_02.png / guide_01.png / guide_02.png
  effects/0/*.json, effects/1/*.json fx 定義（各25種）
  wasm/core.wasm                     WASM コア（ソースは wasm/core.wat）
tools/   アトラス生成・ビルド用スクリプト（運用には不要）
tests/   WASM / DrawData の単体テスト（運用には不要）
```

## A. 描画エンジン

- **WebGL2 レンダラ**に置換。ゲーム画面は単一 `<canvas id="gl">` 内にすべて描画し、DOM は外側の操作パネル・HUD のみ。
- **WASM コア**（`assets/wasm/core.wasm`、ソース `core.wat`）がフレーム毎のホットループを担当:
  - ノーツ／パーティクルの投影バッチ計算（透視・フラット両モード）
  - パーティクル物理更新（重力・ドラッグ・寿命・回転・サイズ）と描画インスタンスのパック
  - WASM が読み込めない環境では同一計算式の JS ミラー実装にフォールバック（テストで両者の一致を検証済み）
- **テクスチャ化＋バッチ描画**: 全ノーツ・帯・矢印・宝石をアトラスから切り出して描画。テクスチャ別のインスタンシングバッチ（背景／白系／ノーツ／エフェクト＋帯ストリップ）で、1フレームの draw call は通常 6〜7 回。
- **透視補正**: 各クアッドが reciprocalW（奥行きの逆数）を持ち、フラグメントシェーダで `uv / recipW` を行う GPU 透視補正を実施。斜めの帯・ノーツでもテクスチャが歪みません。
- **描画解像度**: 内部解像度は 1920×1080 を上限にデバイス比へフィット。ステージ素材は 2048×1176 を使用。

## B. 事前計算とデータ構造

- **DrawData の完全事前計算**（新 `buildPlay`、戻り値 `v:2`）: 読み込み時に以下をすべて計算済みにします。
  - ノーツの表示時刻 `t`（テンポマップ変換済み）とスクロール位置 `q`（ソフラン積分済み visualTime）
  - 同時押し線（同一時刻・同一レイヤー、端から端まで）
  - ロングの帯ポリゴン（ベジェ左右縁を区間分割サンプリング済みの頂点列）
  - ホールド刻み（1/8 小節刻みの中心・幅）、中継点の宝石位置、拍線、コンボ用ヒット時刻列
  - フレーム中の計算は「今見える分の二分探索による選択と描画」だけに限定
- **visualTime の事前変換**: テンポマップとハイスピード（レイヤー別速度区間表）を読み込み時に時刻変換へ畳み込み。SUS 変換は専用パスで実施。
- **状態の一元管理**: `Engine` オブジェクトが現在時刻・曲の長さ・譜面終端・開始遅延・コンボ等を保持し、UI は `Engine.getState()` へ問い合わせるだけ。エンジンと UI の境界を分離（`window.__pl` は互換 API）。

## C. 素材（アセット）

- **テクスチャアトラスの全面採用**: ノーツ2スキン、エフェクト、ステージ、帯、ガイドを「大きな PNG ＋ 切り取り座標表（*.atlas.json）」で管理。座標表は添付に無かったため、透明ピクセルの連結成分から自動検出して生成（再現手順は `tools/build_assets.py`）。
- **ノーツスキン切替**: 設定で `notes_01` / `notes_02` を切替（再生画面・本体設定画面の両方から変更でき、共有設定に保存）。
- **背景設定**: ステージ画像＋背景オーバーレイ画像を分離し、「背景の明るさ（0〜150%）」「ステージカバーの不透明度（0〜100%）」を設定可能。

## D. エフェクト

- **パーティクルシステム**: MikuMikuWorld 由来の設計で、粒の発生・寿命・透明度・重力・ドラッグを物理更新。プール（WASM メモリ内、最大 4096 粒）で使い回し、確保はフレーム中に行いません。
- **エフェクト定義のデータ化**: 添付の `fx_*.json`（25種 × 2パターン）をそのまま読み、専用コンパイラが Unity ParticleSystem 形式（emission バースト、textureSheetAnimation、colorOverLifetime 等）を内部エミッタへ変換。通常／クリティカル／フリック／ロング／トレース／中継／刻み別に割当。レーン光（`fx_lane_*`）は帯状クアッドとして処理。パターンは設定で切替。
- **エフェクト素材**: `effect.png` アトラスから粒の絵を切り出して加算ブレンド描画。

## E. 音声と同期

- **出力遅延の自動補正**: `outputLatency + baseLatency` を自動計測して表示し、再生クロックから差し引いて再同期。
- **タップキャリブレーション**: クリック音（6回予約）に対し「聞こえた瞬間」をタップボタン／Tキー／画面タップで記録し、中央値を補正値として保存。Bluetooth 等の環境差を吸収。
- **手動調整**: 従来の秒単位スライダーに加え、ms 単位スライダー（−500〜+500ms）を新設。

## 既知の近似・制限事項

正直にお伝えするためのメモです。

- **WASM コアは WAT（WebAssembly テキスト形式）の手書き実装**です。担当範囲は投影バッチ計算とパーティクル物理／パックであり、音声・DOM・状態管理は JS 側にあります。「C++／Rust で書かれたフルエンジン」ではありません（この開発環境に C++/Rust の WASM ツールチェーンが無かったため）。計算式は JS ミラーと一致検証済みで、将来 Rust 化する場合は `core.wat` の入出力レイアウトがそのまま仕様になります。
- **effect.png は成分分離できない詰め込みシート**（黒背景・不透明）のため、fx 定義の textureSheetAnimation を画像全体の 8×8 グリッドとして解釈する近似を採っています。粒の絵柄は定義のタイル位置に対応づけていますが、元素材の正確な切り出しではありません。
- **colorOverLifetime** は経過率 0.35 時点の代表 α ＋ フェードイン包絡による近似、**rateOverTime** はティック間隔による近似です。バースト（count / cycleCount / repeatInterval）は遅延キューで再現しています。
- ロング帯の表示範囲（rel）計算はチェイン代表レイヤー基準です（サンプル自体は区間ごとのレイヤーで時刻変換済み）。
- 帯テクスチャ・ガイドテクスチャは添付素材をそのまま使用しています。
